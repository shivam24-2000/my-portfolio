02 — How I operate

Scope beyond my own tickets.

Good engineers add judgement and leverage to the team. This is how that shows up in my work today.

Own the whole lifecycle

Design, tests, code review, CI/CD and production support. I stay with what I ship after it merges.

Design for failure

I assume dependencies will fail: retries, circuit breakers and fault tolerance are part of the design from the start, not patches after an outage.

Backend · AI agent · Python

ColdEmailAgent — autonomous outreach pipeline

An AI agent that runs job outreach from start to finish. It finds the right contact at a company, drafts a personalised email with Claude, queues it for my review, sends it through Gmail, then classifies replies and schedules follow-ups.

  • Serverless-safe scheduling: serverless functions can't keep a scheduler thread alive, so a single idempotent /cron/tick endpoint reads job state from Postgres and runs whatever is due. Leases stop overlapping ticks from running a job twice, and time budgets split long work across ticks so each run stays inside Vercel's 300s limit.
  • Fallback chain for discovery: Hunter.io first, then scraping the company's own pages, then guessed email patterns checked against DNS MX records and the mail server (SMTP), so bounces are caught before sending.
  • Guardrails: an LLM spend ledger with a rolling budget cap, a daily send cap, and 1–3 minute jitter between sends to protect sender reputation.
  • Measured, not vibes: an eval harness runs the reply classifier against 37 hand-labelled cases and reports accuracy, per-label precision and recall, and a confusion matrix.
